## 🎯 Phase 6 目标

将单机战斗原型升级为多人在线游戏，支持 2-4 人组队进行 PvE 战斗。

---

## 📋 核心功能

### 1. 网络架构 ✨

**技术选型**: Godot 4.7.2 MultiplayerAPI + ENet

**架构模式**: 
- **Listen Server** (P2P) - Alpha 阶段
- **Dedicated Server** - Beta 后迁移

**核心组件**:
```
NetworkManager
├── ConnectionManager - 连接管理
├── RoomManager - 房间系统
├── SyncManager - 状态同步
└── RPCManager - RPC 调用
```

### 2. 大厅系统 🏠

**功能**:
- ✅ 创建房间
- ✅ 加入房间
- ✅ 房间列表
- ✅ 玩家准备/取消
- ✅ 开始游戏

**数据结构**:
```gdscript
{
  "room_id": "string",
  "host_id": "int",
  "max_players": 4,
  "current_players": 2,
  "status": "waiting|playing|finished",
  "map": "snow_island",
  "difficulty": "normal"
}
```

### 3. 角色同步 🔄

**同步内容**:
- 位置/旋转（插值）
- 动画状态
- 血量/能量
- 技能冷却
- Buff/Debuff

**同步策略**:
- **关键状态**: 服务器权威
- **位置**: 客户端预测 + 服务器校验
- **视觉**: 客户端优化

### 4. 战斗同步 ⚔️

**技能释放**:
1. 客户端本地播放（即时反馈）
2. 发送 RPC 到服务器
3. 服务器校验（冷却/距离）
4. 广播到其他客户端
5. 应用伤害

**伤害计算**:
- 服务器权威
- 客户端预测显示
- 最终以服务器为准

### 5. 敌人同步 👹

**策略**:
- 仅服务器生成敌人
- 客户端接收敌人状态
- 客户端本地预测移动
- 服务器定期校正

## 🔧 技术要点

### 1. 客户端预测

```gdscript
# 本地立即执行
func cast_skill_local(skill_id: String):
    play_animation(skill_id)
    play_vfx(skill_id)
    start_cooldown(skill_id)

    # 发送到服务器验证
    rpc_id(1, "cast_skill_server", skill_id)

# 服务器验证
@rpc("any_peer", "call_remote")
func cast_skill_server(skill_id: String):
    if not validate_skill(skill_id):
        # 回滚客户端
        rpc_id(sender_id, "skill_rejected", skill_id)
        return

    # 广播给其他玩家
    rpc("cast_skill_remote", sender_id, skill_id)
```

### 2. 位置插值

```gdscript
func _physics_process(delta: float):
    if is_multiplayer_authority():
        # 本地玩家：正常移动
        move_and_slide()
        rpc("sync_position", global_position)
    else:
        # 远程玩家：插值到目标位置
        global_position = global_position.lerp(target_position, 0.3)
```

### 3. 延迟补偿

```gdscript
# 服务器回溯验证
func validate_hit(attacker_id: int, target_id: int, timestamp: float):
    var rewind_time = Time.get_ticks_msec() - timestamp
    var target_past_pos = get_past_position(target_id, rewind_time)

    # 在过去的位置检测命中
    return is_in_range(attacker_id, target_past_pos)
```

## ⚠️ 风险与挑战

### 1. 网络延迟
**风险**: 高延迟导致卡顿  
**缓解**: 客户端预测 + 插值 + 延迟补偿

### 2. 作弊防护
**风险**: 客户端修改数据  
**缓解**: 服务器权威 + 关键数据校验

### 3. 带宽消耗
**风险**: 数据量过大  
**缓解**: 增量更新 + 数据压缩 + 优先级

### 4. 服务器性能
**风险**: 多房间负载高  
**缓解**: Listen Server → Dedicated Server 迁移
